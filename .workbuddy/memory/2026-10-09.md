## 安全规则配置方式更正（重要）

- 操作：云开发控制台 → 数据库 → 点开集合 → 权限设置 → 自定义安全规则（或选预设）→ 保存即生效，无需重部署。5 个协同集合贴 `{"read": true, "write": true}`；其余业务集合用预设「仅创建者可写，所有人可读」；profiles/knowledge_categories 用「仅管理端可写，所有人可读」。

## 材料计划价层：planned_price（冻结计划，不污染总额）
- 用户追问「推进时会不会改计划项的值」→ 确认：状态流转(advanceMaterialStatus)只改 status 不改 total_price，计划总额与每条计划项金额不变；唯一会变的是手动改 total_price（实际价≠计划价）。
- 加 `planned_price` 字段：① 新建材料 planned_price=total_price（录入即计划，定格）；② 编辑时若仍 to_buy（还在计划阶段）planned_price 随录入价更新；③ 已 bought/on_site（已执行）planned_price 定格，只改 total_price（实际成交价）——历史数据无 planned_price 时以编辑前 total_price 为计划基线；④ 推进只改 status，永远不动两价。
- 计算口径（首页 index.js + 花费页 overview.js 各一份，含 `planOf(m)=planned_price??total_price` 回退）：
  - 计划总额 = Σ planOf(全部材料)（冻结，推进不改）
  - 待购(计划) = Σ planOf(to_buy)
  - 已购(实际) = Σ total_price(bought/on_site)
  - 执行率 = Σ planOf(已购项) / 计划总额（推进才变，改实际价不影响条）
  - 偏差 = 已购实际 − 已购计划额（正=超支/负=节省），≠0 时在看板提示
- 改动：material/edit.js（_origStatus/_origTotalPrice + planned_price 规则）、index.js、overview.js、两 wxml（采购计划卡加「实际花费 超支/节省 X」行）。三 JS 过 node --check。
