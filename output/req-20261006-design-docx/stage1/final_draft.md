# 多人协作装修日记本 · 微信小程序设计文档（图文版）

版本 V1.0 ｜ 2026-10-06 ｜ 状态：已评审要点定稿，M1 实施中

## 一、产品定位

以「装修项目」为单位的多人协作装修日记本：家庭成员与好友按时间线或房间共同记录装修全过程（图文日记、施工阶段、材料清单、花费明细），内置可分类检索的装修知识库——内容由全员在 ima 共享知识库中共同记录，再通过小程序链接导入沉淀为小程序端知识库（带图、可评论）。

| 用户 | 核心场景 |
|------|----------|
| 业主（主记录者） | 每天拍照记录施工进展，记花费，随时查知识库 |
| 家庭成员 | 远程查看进度，补充记录，共同核对账单 |
| 好友 | 被邀请查看（只读），给建议 |

## 二、技术架构

前端为微信原生小程序（WXML/WXSS/JS），后端为 WorkBuddy 云服务（数据库、认证、存储、LLM 四个模块），通过 `@tencent-ai/workbuddy-cloud-sdk/miniprogram` 专用入口集成。

关键决策：不依赖实时推送，同步协议设计为「增量拉取为主、推送为增强」的三级降级链；所有写操作携带 version 乐观锁，多人并发编辑冲突时由用户选择保留哪一版。

## 三、页面结构与 tabBar

小程序共 5 个一级标签页（tabBar），加上二级功能页共 13 个页面（M1 范围）。

![tabBar 结构示意图](images/tabbar.png)

| 标签页 | 核心内容 |
|--------|----------|
| 首页 | 当前阶段卡片、预算 vs 已花进度条、最新 3 篇日记 |
| 日记 | 按日分组的时间线，右下角「记一篇」悬浮按钮 |
| 花费 | 预算看板（已花/剩余/分类汇总）、明细列表 |
| 知识库 | 7 大分类横滑、关键词搜索、文章卡片流 |
| 我的 | 我的项目切换、外观（主题）切换、关于 |

二级页面：项目创建、日记详情/编辑、记一笔花费、材料清单/编辑、施工阶段看板、知识文章详情（带图 + 评论）。

## 五、数据模型（13 张表）

数据库全部启用行级安全（RLS），权限唯一事实来源为 members 表，配合三个权限函数：is_project_member / is_project_editor / is_project_owner。

| 表 | 说明 | 关键字段 |
|----|------|----------|
| profiles | 用户档案 | nick_name、avatar_url |
| projects | 装修项目 | name、budget（分）、status、version |
| members | 项目成员（权限载体） | project_id + user_id 唯一、role（owner/editor/viewer） |
| rooms | 房间（预置 6 间） | name、sort_order |
| stages | 施工阶段（预置 8 阶段） | key、status（pending/doing/done）、起止日期 |
| diaries | 图文日记 | title、content、image_paths、room_id、stage_id、version |
| materials | 材料清单 | category、quantity、unit_price、total_price（分）、status |
| expenses | 花费明细 | type、amount（分）、pay_date、version |
| knowledge_categories | 知识分类（预置 7 类） | key、name、sort_order |
| knowledge_articles | 知识文章（带图） | scope（official/shared）、project_id、contributor_id、link_hash、image_paths |
| knowledge_comments | 文章评论 | article_id、content（可见性跟随文章） |
| revisions | 编辑历史 | collection、doc_id、prev/new_version |
| invites | 邀请码（M2） | code、role、expire_at、status |

约定：金额一律整数分存储；version 为乐观锁；日记与花费软删除（deleted 标记）。

## 六、知识库集成（ima 共享库 → 小程序）

分层模型：

| 层 | 内容来源 | 可见范围 | 写入方式 |
|----|----------|----------|----------|
| 官方预置库 | ima「装修小常识」批量整理 | 全小程序只读 | 运维脚本导入 |
| 项目共享库 | 成员在同一 ima 共享库共建的笔记（含现场图） | 本项目成员 | 小程序导入页，链接导入 |
| 公共广场（V1.x 可选） | 项目共享中被推荐的内容 | 全小程序 | 推荐 + 审核 |

分工边界：ima 共享库负责「日常共建」（快、随意、可反复改）；小程序知识库负责「精选沉淀」（带分类标签、配图与评论，可与施工阶段/花费对照检索）。导入是主动的精选动作，语义为「快照沉淀」，不做双端同步；按 link_hash 去重。

链接解析三级降级：P1 ima 开放 API → P2 抓取免登录 H5 分享页 → P3 手动粘贴正文（必做兜底）。落地前需实测 ima 分享链接形态。

## 七、多人协作与实时同步

角色权限矩阵（服务端 RLS 强制，前端仅做显隐）：

| 能力 | owner | editor | viewer |
|------|:-----:|:------:|:------:|
| 查看项目全部内容 | ✓ | ✓ | ✓ |
| 写/改日记、材料、花费 | ✓ | ✓ | — |
| 更新施工阶段状态 | ✓ | ✓ | — |
| 邀请成员 / 改角色 / 移除 | ✓ | — | — |
| 项目设置、删除项目 | ✓ | — | — |

同步规格：每集合记录 lastSyncAt，页面 onShow 与下拉刷新时增量拉取（updated_at 大于游标的记录，含删除墓碑）；实时性分三级——L1 云端推送（验证可用后启用）、L2 前台轮询 20 秒、L3 仅 onShow。

写冲突：编辑页进入时记录 baseVersion，提交时「id + version」双条件更新；冲突时提示并拉取最新版本，由用户选择保留哪版。所有受控写操作追加 revisions 记录。
